# keirin

競輪の期待値評価のためのデータベースと収集基盤。

目的は「よく当たる予想」ではなく、**長期回収率が100%を超える賭けだけを選別できる状態**を作ること。
控除率が約25%あるため、市場（オッズ）より33%以上うまく確率を推定できなければ勝てない。

- 戦略と検証プロトコル: [`docs/STRATEGY.md`](docs/STRATEGY.md)
- データソース調査結果（robots.txt / API仕様）: [`docs/DATA_SOURCES.md`](docs/DATA_SOURCES.md)
- スキーマ定義: [`sql/schema.sql`](sql/schema.sql)

## いちばん重要なこと

**オッズの時系列収集を今日から動かすこと。**

レース結果や出走表は後からいくらでも遡れる。
だが**締切前オッズの履歴はどこにも売っていない。取り逃したら永久に手に入らない。**

「自分の予測 vs 市場」の差＝妙味を測るには締切直前オッズが必須で、
前日オッズでバックテストすると実際には買えない価格で幻の利益が出る。

したがってモデルを1行も書く前に、まず収集を回す。

```bash
python -m keirin.collect watch
```

これを止めないことが Phase 0 の唯一の仕事。

## セットアップ

収集だけなら Python 3.11+ 以外に何も要らない（標準ライブラリのみで動く）。
何ヶ月も回り続けるプロセスなので、依存で壊れるリスクを持ち込んでいない。

```bash
# 収集のみ
export PYTHONPATH=src

# DuckDB への投入・分析もする場合
pip install -e '.[analysis]'
```

## 使い方

```bash
# 年間の開催カレンダーを取得（1リクエストで年間分）
python -m keirin.collect calendar --year 2026

# ある日のレース一覧と締切時刻を確認
python -m keirin.collect plan --date 20260811

# 収集本体。締切前オッズを刻んで貯め続ける
python -m keirin.collect watch

# 確定した結果・払戻をバックフィル
python -m keirin.collect results --date 20260811

# raw -> DuckDB
python -m keirin.load --data-root data --db data/keirin.duckdb
```

`watch` は日付が変わると当日の開催を自動で読み直すので、
`systemd` や `supervisor` で常駐させておけばよい。

### オッズを刻む間隔

締切の 3600/2700/1800/1200/900/600/420/300/240/180/120/90/60/40/25/15 秒前と、
締切20秒後に取得する。締切直前ほど密なのは、**実際に買えるのは締切直前の価格**だから。

`official_dt`（オッズの公式時刻）が前回と同じなら保存しない。
市場が動いていないのに行だけ増やしてもディスクを食うだけで情報が増えない。

## データ構造

```
data/raw/<api_class>/dt=<YYYYMMDD>/part.jsonl.gz   ← 生レスポンス。不変・追記のみ
data/keirin.duckdb                                  ← 正規化テーブル。raw から再構築可能
```

**Raw 層は必ず残すこと。** パース仕様は必ず後で変えたくなる。
生データさえあれば作り直せるが、正規化済みだけ持つと後から項目を足せない。
再取得できないオッズでは致命的になる。

主要テーブル:

| テーブル | 内容 |
|---|---|
| `races` | 開催日, 場, R番号, 距離, 車立, **締切時刻**, 天候, グレード |
| `entries` | 車番, 枠番, 選手, 級班, **競走得点**, 脚質, ギヤ倍数, 決まり手内訳 |
| `race_lines` | **ライン構成**（ライン番号 × ライン内位置 × 車番） |
| `odds_snapshots` | 賭式 × 組番 × **official_dt** のオッズ時系列 |
| `results` | 着順, 着差, 上りタイム, **決まり手**, S/B |
| `payouts` | 全賭式の確定払戻・人気 |

`final_odds` ビューは各組番の最終オッズ（＝実際に買えた価格）を返す。
**バックテストは必ずこれを使うこと。**

## 収集マナー

- リクエスト間隔は**最低1.5秒**（`NetkeirinClient` がプロセス内でグローバルに直列化）
- 失敗時は指数バックオフでリトライし、諦めたら次へ進む（収集を止めない）
- 収集元は robots.txt で許可されている netkeirin のみ。
  公式 keirin.jp はレースデータページを robots.txt で拒否しているため使わない
  （選手マスタとバンク諸元は許可パスから取得可）

ブロックされて収集が止まることが最大の損失なので、速度より継続性を優先している。
