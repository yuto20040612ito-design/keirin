# 競輪で回収率100%超を目指すための戦略

目的: **実弾で長期回収率 > 100%**。当てることではなく、期待値がプラスの賭けだけを繰り返すこと。

---

## 0. 現時点の結論: エッジは見つかっていない

**最も重要な検定結果を先に書く。**

log loss を「市場との差」で測ると、特徴量を足すごとに順調に縮んできた
（0.3627 → 0.1540、約58%を回収）。だがこれは**エッジの証拠ではない**。

本当に知りたいのは「市場に勝てるか」ではなく、
**「市場が知らない情報を持っているか」**。これは直接検定できる。

市場のインプライド確率の対数を特徴量として入れたモデルを作り、
そこに自前の特徴量を足して改善するかを見る（`keirin.baseline` が出力する）:

| | log loss |
|---|---|
| 市場のみ | **1.3230** |
| 市場＋自前特徴 | 1.3354 |

**上乗せ分 −0.0125（95%CI −0.0335〜+0.0080）。**

つまり自前の特徴量を足しても改善せず、むしろわずかに悪化している
（有意ではない）。**市場が既に織り込んでいる情報しか持っていない。**

この状態で賭ければ、控除率25%のぶんだけ確実に負ける。
実際 Phase 4 のバックテストでも回収率は100%に届いていない。

### この結果の意味

競走得点・ライン・脚質・実績はどれも予測に効いた（log loss は改善した）。
だが**それらは全部、市場も知っている**。公開情報を上手に使っても、
同じ公開情報を見ている市場を超えることはできない、という当然の結論に落ちる。

エッジを探すなら、方向はこの3つのどれか:

1. **市場が持っていない情報を持つ** — 締切前オッズの動き（資金の流れ）は
   その候補。`watch` を回さないと手に入らないので、まず貯める。
2. **市場が構造的に歪む場所を探す** — favorite-longshot bias、
   薄い市場（ミッドナイト、人気薄の目）など。全体では効率的でも
   部分市場では歪んでいる可能性がある。→ **調べた。下記参照。**
3. **エッジは無いと結論する** — これも正当な結論。
   その場合の正解は「賭けない」。

**やってはいけないのは、上乗せが有意でないまま実弾を入れること。**

### favorite-longshot bias は実在した。ただし足りない

`keirin.segments` でオッズ帯別の回収率を出した（全1360レース、各帯を全部買う）。
控除率が一律なら、どの帯も約75%になるはず。

| オッズ帯 | 2車単 | 3連単 |
|---|---|---|
| 1-5倍 | 77.2% | **87.9%** |
| 5-10倍 | **82.1%** | 75.5% |
| 10-20倍 | 75.9% | 77.7% |
| 20-50倍 | 72.6% | 78.5% |
| 50-100倍 | 74.8% | 70.4% |
| 100-500倍 | **53.0%** | 67.9% |
| 500倍以上 | 46.8% | 61.1% |

**オッズが上がるほど回収率が下がる**という、教科書どおりの
favorite-longshot bias が両賭式で出ている。人気薄が過剰に買われている。

個々の帯の信頼区間は広い。だが**帯を跨いで単調に下がっている**という事実は、
単一の帯がたまたま外れるより起こりにくい。バイアス自体は実在すると見てよい。

**それでも賭ける根拠にはならない。**
いちばん良い帯（3連単1-5倍）でも87.9%（95%CI 73.7〜102.5%）で、
**100%に届いていない**。控除率25%を跳ね返すには足りない。

「75%より良い」と「100%を超える」の間には大きな隔たりがある。
バイアスがあること自体は、儲かることを意味しない。

### 多重比較に注意

この分析では30件近い検定を行っている。95%信頼区間を30回引けば、
歪みが1つも無くても期待値1.5件は「有意」に見える。

Bonferroni 補正なら有意水準は 0.05/30 ≒ 0.0017、
つまり99.8%信頼区間で見る必要がある。この基準では**どれも有意ではない**。

`keirin.segments` は検定数を数えて、補正がどれだけ必要かを出力する。
歪みを見つけたと思ったら、以下を全部通してから賭けること:

1. その帯だけを**別期間のデータで追試**する
2. **なぜ歪むのか事前に説明がつくか**（後から理由をつけるのは簡単。順序が重要）
3. **自分の投票でオッズが下がる分**を差し引いても残るか

## 1. 何と戦っているのか

競輪の控除率は約25%。**何も考えずに買えば回収率は75%に収束する。**

実測しても確かにそうなっている（20260810 の59レース、確定オッズから `1/Σ(1/オッズ)`）:

| 賭式 | 払戻率 |
|---|---|
| 2車複 | 73.9% |
| 2車単 | 74.4% |
| 3連複 | 74.4% |
| 3連単 | 74.8% |

これがスタート地点。ここから25ポイント以上を自力で取り返さないと勝てない。

つまり必要なのは「よく当たる予想」ではなく、**市場（オッズ）より33%以上うまく確率を推定すること**。
そしてオッズは数万人の投票の集約なので、すでにかなり賢い。
「強い選手を当てるモデル」を作っても市場に勝てない — それは市場がすでに織り込んでいる。

> 勝ち筋は「良い予想をすること」ではなく、**「市場が構造的に間違っている場所を見つけること」**。

### 狙うべき歪みの仮説

以下は検証すべき仮説であって、事実として扱ってはいけない。すべてデータで確かめる。

| 仮説 | 根拠 | 検証方法 |
|---|---|---|
| **favorite-longshot bias** | 公営競技全般で、人気薄が過剰に買われ堅い目が過小評価される傾向 | オッズ帯別の回収率を実測。単調性を見る |
| **3連単の端の目** | 9車で504通り。人気薄の組ほど値付けが雑になりやすい | 人気順位帯 × 回収率 |
| **ライン評価のズレ** | 一般の予想は選手個人の強さに引っ張られ、ライン構成・先行争いの評価が甘くなりやすい | ライン構成特徴量のモデル寄与度と、市場オッズとの残差 |
| **マイナー場・ミッドナイト** | 投票参加者が少ない＝市場の情報集約が弱い＝効率が落ちる | 場別・時間帯別の市場効率（対数オッズの予測力） |
| **締切直前のオッズ変動** | 直前の資金流入に情報が含まれる／逆に過剰反応する | 早い時点のオッズと締切オッズの差の予測力 |

これらは**全部ハズレの可能性がある**。ハズレだと分かることも成果として扱う。

## 2. 最優先事項: オッズ時系列を今日から貯める

**これが戦略上いちばん重要な一点。**

- レース結果・出走表は**後からいくらでも遡れる**
- **締切前オッズの履歴は、どこにも売っていない。取り逃したら永久に手に入らない**

「自分の予測 vs 市場」の差＝妙味を測るには締切直前のオッズが必須。
さらに、バックテストを前日オッズでやると**幻の利益**が出る（実際に買える価格ではないため）。

したがって、モデルを1行も書く前に、まずオッズ収集を動かす。
これが `keirin.collect` の `watch` サブコマンドで、Phase 0 の唯一の内容。

```
python -m keirin.collect watch
```

半年後に「データがない」で詰むのを避けるための投資であり、後から取り返しがつかない唯一の工程。

## 3. データベース設計の考え方

3層構成（Raw → Staging → Mart）。

```
data/raw/         取得した生レスポンスをそのまま JSONL.gz で追記保存（不変・追記のみ）
       ↓ load
data/keirin.duckdb  正規化テーブル（races/entries/results/lines/odds_snapshots/payouts/players）
       ↓ feature
       特徴量マート（学習用のワイドテーブル）
```

**Raw層を必ず残すこと。** パース仕様は必ず後で変えたくなる。生データさえあれば作り直せるが、
生データを捨てて正規化済みだけ持つと、後から新しい項目を足せない。
再取得できないオッズでは致命的になる。

主要テーブルは `sql/schema.sql` に定義。設計上の要点:

- `odds_snapshots` は `(race_id, bet_type, combination, official_dt)` が主キー。
  `official_dt` が変わったときだけ行が増えるので、重複なく時系列が積み上がる。
- `race_lines` はライン構成を「ライン番号 × ライン内位置」で正規化して持つ。
  netkeirin の `lineForecast` の `"0"` 区切りをそのまま展開したもの。
- `entries` と `results` を分けているのは、**出走表は締切前に確定し、結果は締切後に確定する**ため。
  この時間差を混ぜると簡単にリークする。

## 4. 特徴量の方針

### 選手単体
競走得点、直近N走の着順、S/H/B回数、決まり手構成比（逃/まくり/差し/マーク）、
勝率・連対率、級班、年齢、期別、ギヤ倍数、休養明け日数

### レース内相対
レース内での競走得点順位、得点差（トップとの差・平均との差）、
レース内の「先行タイプ」人数（＝先行争いの激しさ）

### ライン（競輪の本質）
ライン人数、ライン内位置（先頭/番手/3番手/単騎）、
自ライン先頭の先行力、他ラインとの戦力差、同地区度合い、単騎の数

### 環境
バンク周長（333/400/500）、みなし直線距離、カント、
風向・風速、気温、ナイター/ミッドナイト区分、開催日次（初日/2日目/最終日）、グレード

### 市場（最重要）
締切N分前のオッズ、支持率、早い時点からのオッズ変動量

**市場特徴量の扱いには注意。** オッズをモデルに入れると精度は上がるが、
それは「市場をコピーしているだけ」になりやすい。
狙いは市場超えなので、**まず市場なしでモデルを作り、市場と比較する**。
市場を入れるのは「市場＋α」を作ると決めた段階から。

## 5. モデリング

競輪は**レース内で1人だけが勝つ**構造なので、独立な二値分類は理論的に間違っている
（レース内の確率合計が1にならない）。

### 推奨アプローチ

1. **条件付きロジット / Plackett-Luce**
   各選手に強さスコアを出し、**レース内で softmax 正規化**。合計が1になる。
   実装は LightGBM の `lambdarank` でも近似できる。

2. **決まり手の多クラス予測 → 展開シミュレーション**
   「誰が強いか」ではなく「**どう決まるか**」を予測する。
   逃げ/まくり/差し/マークの発生確率を予測し、モンテカルロで展開を回して
   3連単504通りの確率を生成する。競輪の構造に最も素直な形。

3. **キャリブレーション必須**
   予測確率がそのまま期待値計算に入るので、確率が歪んでいると全部壊れる。
   isotonic regression か Platt scaling で較正し、reliability diagram で確認する。

### 評価指標

- **Log loss / Brier score** — 確率の質。精度より先にこれを見る
- **回収率 (ROI)** — 最終目標
- **市場との比較** — 同じレースでオッズから逆算した確率の log loss と比べる。
  **これに負けているうちは絶対に賭けてはいけない**

## 6. 賭け方（ここで勝敗が決まる）

モデルではなく賭け方が収支を決める。

### 購入条件

```
EV = p × odds − 1  >  threshold
```

`threshold` は 0 ではなく、モデル誤差のマージンを取って 0.1〜0.2 程度から始める。
`p` が過大評価されているときに買うのが一番の破滅パターンなので、閾値は保守的に。

### 資金配分

**fractional Kelly（1/4〜1/2ケリー）**。フルケリーは推定確率が少しでも過大だと破産する。
競輪の `p` 推定はノイズが大きいので、1/4ケリーから始める。

### バックテストの鉄則

1. **必ず締切オッズを使う。** 前日オッズでの検証は幻の利益を生む
2. **パリミュチュエルの自己影響を織り込む。** 自分の投票でオッズは下がる。
   薄い市場（ミッドナイト、人気薄の目）ほど影響が大きい。
   「その組の売上に対して自分がいくら入れるか」でオッズ低下を見積もる
3. **控除率を確認する。** バックテストの回収率が75%付近なら、それは何も見つけていない証拠

---

### バンク特性を足した結果（検証425レース）— 効かなかった

公式 keirin.jp からバンク諸元（周長・みなし直線・カント・方位・
当該バンクの1着決まり手構成）を取り、選手側の属性との交互作用として入れた。
バンク諸元はレース内で一定なので、そのまま入れても softmax で消えてしまうため。

| | log loss | 市場との差 | 1つ前からの改善 |
|---|---|---|---|
| 競走得点のみ | 1.6918 | +0.3627 | — |
| ＋ライン・展開 | 1.5865 | +0.2573 | +0.1054（有意） |
| ＋脚質・実績 | 1.4831 | +0.1540 | +0.1033（有意） |
| ＋バンク特性 | 1.4822 | +0.1530 | **+0.0010（有意でない）** |
| 市場 | 1.3291 | — | — |

**バンク特性の寄与は +0.0010、95%CI −0.0042〜+0.0057 でゼロと区別できない。**

考えられる理由:
- バンクの決まり手構成は、選手側の脚質・決まり手構成で既に説明されている
- 交互作用の取り方が粗い（`is_line_head × みなし直線` 程度では足りない）
- そもそもバンク差は市場も選手も織り込み済みで、残差に効かない

データ自体は43場ぶんの静的情報で収集コストがほぼゼロなので、
**捨てずに残す**。風向を収集できるようになれば、バンクの方位と組み合わせて
「向かい風の直線」を作れる。そこで初めて効く可能性がある。

### 脚質・実績の効果は追試で確定した

Phase 3 の時点では脚質の改善は +0.0695（95%CI +0.0036〜+0.1348）で、
下限がほぼゼロに接していたため保留扱いにしていた。

検証レース数を200→425に増やした結果、**+0.1033（95%CI +0.0620〜+0.1446）**
となり、下限が明確にゼロから離れた。**効果は本物**と判断してよい。

サンプルを増やすまで判断を保留したのが正しかった、という一例。

### Phase 4 の初回実測（学習432 / 較正136 / 検証132レース）

**エッジは見つかっていない。** 想定どおりの結果。

較正は素直だった。べき変換のパラメータは a = 1.10 で、
予測確率と実際の勝率もよく一致している:

| 予測 | 実際 | 件数 |
|---|---|---|
| 0.008 | 0.017 | 117 |
| 0.038 | 0.034 | 117 |
| 0.106 | 0.094 | 117 |
| 0.254 | 0.256 | 117 |
| 0.473 | 0.470 | 117 |

期待値ベースで100円均等に買った結果:

| EV閾値 | 2車単 回収率 | 3連単 回収率 |
|---|---|---|
| 0.0 | 70.4% | 62.4% |
| 0.1 | 77.2% | 62.0% |
| 0.2 | 84.4% | 66.2% |
| 0.3 | **91.3%** | 71.3% |
| 0.5 | 81.3% | 71.1% |

閾値を上げると回収率が上がる傾向は見えるが、
**どの閾値でも100%に届いておらず、95%CIは30〜160%と話にならないほど広い**。
控除率25%（＝無選別なら75%）と統計的に区別できていない。

つまり現時点では「エッジがある」とは到底言えない。
132レースでは何も判定できないという、Phase 2 と同じ結論に戻ってくる。

#### この数字がまだ楽観側に偏っている理由

1. **確定オッズで購入判断している。** バックフィルには締切前オッズが無いため。
   実際に見られるのは締切前の価格だけなので、これは未来を覗いていることになる。
   `watch` で締切前オッズが貯まったら `decision_odds` に切り替える必要がある。
2. **自分の投票によるオッズ低下を織り込んでいない。** パリミュチュエルなので、
   買った瞬間にその組のオッズは下がる。薄い市場ほど影響が大きい。
3. **Harville 近似は2着以降で歪む。** 1着確率から順序対を作る際の仮定が現実と
   ずれることが知られている。

この3つはいずれも回収率を実際より良く見せる方向に効く。

## 7. 検証プロトコル

- **時系列split（walk-forward）必須。** ランダムsplitは即リーク
- **同一開催を学習とテストに跨がせない。** 同じ開催内は選手・条件が重複するため
- **未来情報の混入チェック。** 結果由来の項目（上りタイム、決まり手）を特徴量に入れない。
  これは事故が起きやすい最頻出のバグ
- **サンプル数と信頼区間。** 回収率は分散が非常に大きい。
  「回収率120%」でも試行数が少なければ何の意味もない。ブートストラップで区間を出す

### 実例: 59レースで「回収率117.7%」が出る

人気帯別に3連単の回収率を出したところ、実際にこうなった:

| 人気帯 | 購入点数 | 回収率 |
|---|---|---|
| 1-10番人気 | 590 | 78.7% |
| 11-50 | 2,360 | 48.4% |
| 51-150 | 5,635 | **117.7%** |
| 151番人気以下 | 3,235 | 0.0% |

51-150番人気帯だけ100%を超えている。favorite-longshot bias の仮説に合う形にも見える。

**が、これは何も意味していない。** この帯の的中はわずか14本で、
的中数の相対誤差はおよそ 1/√14 ≒ 27%。回収率の1σ区間は概ね 86〜150% になり、
**75%と統計的に区別できない**。

59レースはサンプルとして桁が足りない。この手の数字を見て嬉しくなった時点で負けている。
仮説を検証するには最低でも数千〜数万レース、かつブートストラップでの区間推定が要る。
- **ペーパートレード。** 実弾投入前に最低3〜6ヶ月、実際の締切オッズでシミュレーション

## 8. ロードマップ

| Phase | 内容 | 完了条件 |
|---|---|---|
| **0** | **オッズ収集の常時稼働** | `watch` が毎日止まらずに回り、raw が日々増えている |
| **1** | 過去レース結果のバックフィル | 数年分の結果・出走表・ラインが DuckDB に入る |
| **2** | ベースライン（競走得点のみ） | **市場に負けることを数字で確認する** |
| **3** | ライン・展開・環境の特徴量追加 | log loss がベースラインから有意に改善 |
| **4** | キャリブレーション＋期待値バックテスト | 締切オッズで回収率100%超の領域が特定できる |
| **5** | ペーパートレード3〜6ヶ月 | 実測回収率が信頼区間の下限で100%を超える |
| **6** | 実弾（小額から） | — |

### Phase 2 を飛ばさない

「わざと負けを確認する」工程は必須。
ベースラインが市場にどれだけ負けるかを知らないと、
後の改善が本物か、それとも過学習か、判別できなくなる。

### Phase 2 の実測（675レース / 検証222レース）

競走得点だけの条件付きロジット。学習と検証は開催日の境界で分けてある。

| | log loss | top1 |
|---|---|---|
| 一様分布 | 1.9785 | 24.8% |
| ベースライン（競走得点のみ） | 1.7051 | 36.0% |
| 市場（2車単から周辺化） | **1.3631** | **48.6%** |

**ベースライン − 市場 = +0.3420（95%CI +0.2489〜+0.4384）**

競走得点だけでも一様分布よりは明確に良い（1.98 → 1.71）。
しかし市場には有意に負けている。信頼区間の下限が0を上回っているので、
「たまたま負けた」ではなく「実力で負けている」と言い切れる。

**これが出発点。** 埋めるべき差は log loss で約0.34。
ここからライン・展開・環境の特徴量を足して、この差を詰めていく。

なお222レースはまだ少ない。差の符号は動かないだろうが、
Phase 3 以降で「改善したかどうか」を判定するには数千レース規模が要る。

### Phase 3 の実測（666レース / 検証220レース）

ライン特徴量を追加した。両モデルは同一レース集合を見ている。

| | log loss | top1 |
|---|---|---|
| 一様分布 | 1.9777 | 25.0% |
| 競走得点のみ | 1.7019 | 35.9% |
| ＋ライン・展開 | **1.6237** | **40.5%** |
| 市場 | 1.3701 | 48.2% |

**ライン特徴量による改善 = +0.0781（95%CI +0.0130〜+0.1368）** — 有意。

市場との差は **0.3318 → 0.2536** に縮まった。差の約24%を回収したことになる。
ただし残り0.25はまだ有意に負けており、市場超えには遠い。

#### モデルが学習した構造は実データと一致する

ライン内位置ごとの実際の勝率:

| ライン構成 | 1番手 | 2番手 | 3番手 |
|---|---|---|---|
| 3人ライン | 24.5% | 23.2% | **2.3%** |
| 2人ライン | 15.7% | 7.0% | — |
| 単騎 | 11.5% | — | — |

決まり手も裏付けている。1番手が勝つときは捲・逃（自力）、
2番手が勝つときはほぼ差し（241件）＝番手差し、3番手はほとんど勝たない。

**先頭と番手はほぼ互角で、3番手だけが壊滅的**というのが競輪の構造。
「ライン先頭が強い」でも「番手が有利」でもない。

#### 係数の解釈には注意

標準化後の係数は `line_pos` が −1.35、`is_line_head` が −0.80 と、
一見矛盾して見える。これは両者が強く相関している（`is_line_head` は
`line_pos == 1`）ためで、**個々の係数は単独では解釈できない**。
2つ合わせて「1番手 ≒ 2番手 ≫ 3番手」を表現しており、上の実測と整合する。

同様に `rating`（+0.18）が `line_rating_mean`（+1.30）より小さいのも、
両者が相関しているため。「個人の得点より所属ラインの強さが効く」と読みたく
なるが、この係数だけを根拠にそう言うことはできない。

`is_s_class` が 0 なのは、この期間の対象がA級中心で分散が無かったため。

### Phase 3 続き: 脚質・実績を足す（700レース / 検証200レース）

ライン内位置は脚質の代理変数でしかない。実際の脚質（逃/追/両）と、
バック回数・決まり手構成といった実績値を出走表HTMLから足した。

| | log loss | top1 | 市場との差 |
|---|---|---|---|
| 一様分布 | 1.9591 | 21.0% | — |
| 競走得点のみ | 1.6753 | 36.0% | +0.3703 |
| ＋ライン・展開 | 1.5617 | 44.5% | +0.2567 |
| **＋脚質・実績** | **1.4923** | 44.0% | **+0.1873** |
| 市場 | 1.3050 | 48.0% | — |

段階ごとの改善（いずれも同一レース集合、95%CI）:

| 追加 | 改善 | 95%CI | 判定 |
|---|---|---|---|
| ライン・展開 | +0.1136 | +0.0556〜+0.1709 | 有意 |
| 脚質・実績 | +0.0695 | +0.0036〜+0.1348 | 有意（ただし下限がほぼ0） |

**市場との差は 0.3703 → 0.1873 で、約49%を回収した。**

ただし脚質・実績の改善は信頼区間の下限が +0.0036 とほぼゼロに接している。
「有意」と出てはいるが、サンプルを増やすと消える可能性が十分ある。
現時点で確信を持って言えるのはライン特徴量の効果までで、
脚質の上乗せは保留扱いにしておくのが妥当。

なお top1 は 44.5% → 44.0% とわずかに下がっている。
log loss は改善しているので確率の質は上がっているが、
**top1 と log loss は別物**であることの実例になっている。
期待値ベースで賭ける以上、見るべきは確率の質（log loss）のほう。

---

## 9. 正直に置いておくべき前提

- 控除率25%は重い。**多くの試行は回収率100%に届かずに終わる**
- 見つけた歪みは、他人も見つければ消える。エッジには賞味期限がある
- 回収率のばらつきは極めて大きく、**数百レース程度では実力と運が分離できない**
- したがって Phase 5 のペーパートレードを省略した実弾投入は、
  「エッジがある」ことではなく「たまたま勝った」ことに賭ける行為になる

このプロジェクトの成功条件は「儲かること」ではなく、
**「エッジがあるかないかを、自分を騙さずに判定できる状態を作ること」**。
判定した結果エッジがないなら、賭けないことが正しい結論になる。
