# スマホだけで収集を始める

PCもサーバーも要らない。**GitHub の画面だけ**で完結する。

集めたオッズは自動でこのリポジトリにコミットされるので、
データがどこかに消える心配もない。スマホからいつでも中身を見られる。

---

## 先に知っておくこと

**リポジトリを public（公開）にする必要がある。**

GitHub Actions の無料枠は、

| | 無料枠 |
|---|---|
| public リポジトリ | **無制限** |
| private リポジトリ | 月2,000分（Freeプラン） |

この収集は1日あたり16時間ほど動かすので月に約29,000分になる。
**private のままでは2日で枠が尽きる。**

公開して困るものは入っていない（コードと、誰でも見られる公開オッズだけ）。
それでも嫌なら、[エックスサーバーでの手順](SETUP_XSERVER.md) を見ること。

---

## 手順（スマホのブラウザだけ）

### 1. リポジトリを公開にする

`Settings` → 一番下 `Danger Zone` → `Change repository visibility`
→ `Change to public`

### 2. 収集用のブランチを main に取り込む

リポジトリの `Pull requests` → `New pull request`

- base: `main`
- compare: `claude/keirin-victory-database-oix02a`

作成して `Merge pull request`。

**これで収集が始まる。** schedule はデフォルトブランチ（main）でしか
動かない仕様なので、取り込むまでは1分も消費しない。

### 3. すぐ試したいとき

翌朝を待たずに動かせる。

`Actions` タブ → 左の `collect odds` → `Run workflow`
→ 終了時刻（JST）を入れて実行。

### 4. 動いているか見る

`Actions` タブを開けば実行履歴が並ぶ。緑のチェックが付いていれば成功。

各実行の最後に収集状況が表示される:

```
  最後に取得できた時刻:
    オッズ          2026-08-13 12:31  (0.1時間前)
  → 収集は動いているように見える。
```

集まったデータは `data/raw/` に自動コミットされる。
コミット履歴が毎日増えていれば動いている証拠。

---

## どういう仕組みか

1日を3枠に割って、それぞれ長時間のジョブとして走らせる。

| 開始 (JST) | 終了 (JST) |
|---|---|
| 07:20 | 13:00 |
| 12:50 | 18:30 |
| 18:20 | 23:59 |

### なぜ「毎分 cron」にしないのか

GitHub の schedule は**最短5分間隔**で、しかも公式ドキュメントに
「高負荷時は遅延する（毎時0分付近が特に混む）」と明記されている。

こちらがやりたいのは**締切15秒前のオッズ**を取ることなので、
外から起こされるタイミングは信用できない。

そこで、起動は1日3回だけにして、**細かい時刻の制御はプログラムの内部に持たせた**。
一度起動したら自分で次の締切まで眠り、正確な時刻に起きる。

### なぜ 6 時間で区切るのか

GitHub Actions は1ジョブ6時間で強制終了される。
強制終了されると、それまでに集めたデータをコミットする機会が無くなる。

そこで `--until` で**自分から終了する**ようにしてある。
終了後に必ずコミットするので、データが飛ばない。

---

## 弱点

**枠の切れ目で数分の穴が空くことがある。** GitHub 側の遅延のためで、
避けようがない。ただし欠けるのは「締切前オッズの推移」だけで、
レース結果と確定オッズは後からでも取れる。

**60日間リポジトリに何も動きが無いと schedule が自動停止する**（public の仕様）。
毎日データをコミットするので通常は起きないが、
長期間止めた後に再開するときは Actions タブから手動で有効化すること。

**リポジトリが太る。** 1日3〜4MB 程度なので1年で1GB強になる。
そうなったら古い raw を別リポジトリや手元に移すこと。

---

## 分析はどうするか

分析には DuckDB などが要るので、スマホでは無理。
データが貯まったらPCに落として:

```bash
git pull
python -m keirin.load --data-root data --db data/keirin.duckdb
python -m keirin.baseline --db data/keirin.duckdb
```

**収集さえ止めなければ、分析はいつでもできる。**
逆に収集を止めた日のオッズは二度と手に入らない。
だからまず収集を動かすこと。
